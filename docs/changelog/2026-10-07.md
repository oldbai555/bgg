**踩过的坑 —— 绝对不要再犯**：

> - 现象：手机端提示框里出现整串 `保存打卡失败: rpc error: code = InvalidArgument desc = ...`。根因：网关 logic 的业务错误走 go-zero 默认 `httpx.Error`，返回 HTTP 400 + text/plain 原文，不是 JSON 信封；前端原来只认 JSON 的 `msg`。正确做法：前端统一用 `plainErrorMessage` 取 `desc = ` 之后的部分；后端 RPC 侧 `status.Error(codes.InvalidArgument, "给用户看的话")` 写成人话。
> - 现象：后台「使用者」页报 `Cannot read properties of undefined (reading 'slice')`，数据明明正常。根因：Element Plus 的 `el-table-column` 初始化时会拿空 `row` 调一次默认插槽（探测子列），`row.nickname.slice()` 直接炸。正确做法：表格插槽里对行字段做方法调用一律先兜底（`(row.nickname || '').slice(0, 1)`、`row.content?.xxx`）。
> - 现象：周计划抽屉打开后是空的。根因：父组件 `v-if="weekTarget"` 和 `weekVisible = true` 在同一 tick 设置，`el-drawer` 挂载时就已经是打开状态，不会触发 `@open`，`load()` 没跑。正确做法：不依赖 `@open`，在组件里 `watch([visible, templateId], ..., {immediate: true})` 加载。
> - 现象：设计时以为普通使用者（没有任何角色）拿不到字典，手机端标签会显示成数字，差点为手机端另开一个公开字典接口。根因：误以为 `/dict/batch` 挂了 Permission；核实 `admin.api` 后它只挂 Auth + ApiEnabled。正确做法：手机端字典照常走 `/dict/batch`（`FITNESS_DICT_CODES` 并进 `REQUIRED_DICT_CODES` 给后台用，手机端不走后台登录收尾，由 `composables/useFitnessDicts.ts` 进页时按需补拉），不要为手机端另开一个"公开字典"接口。
> - 现象：手机端登录页也上报到 `fitness_today`，PV 虚高。根因：复用了今日页的 metric module。正确做法：每个页面一个 module，新增 module 要同时改 `metric_module` 字典和 iam-rpc `isValidMetricModule` 白名单，否则上报被静默丢弃。
> - 现象：提交前 AI 审查（Gentleman Guardian Angel）指出：后台新建模板/通用提示时如果不带 status，存进去就是禁用。根因：一开始 status 用 1 启用 / 0 禁用，而 `.api` 里 status 是 `optional`，不传会解析成 0，Logic 显式写入 0，建表的 `DEFAULT 1` 根本不起作用。正确做法：带 `optional` 的状态字段不要让 0 承担业务含义（0 = 没传），改成 1/2，并在 domain 层 `statusOrDefault` 兜底。
> - 现象：前端提交被同一个审查拦下，`trainingStatus === 1`、`trainingPreference: 1`、`'/front/fitness/checkin'` 这类裸数字/裸路径散在多个页面。根因：后端改了常量，前端只改了 `status`，其余枚举和路由没跟上。正确做法：fitness 前端的枚举值（`FitnessStatus`/`FitnessTrainingStatus`/`FitnessTrainingType`/`FitnessTrainingPreference`/`FitnessSuggestionStatus`）和路由路径（`FITNESS_*_PATH`）统一从 `constants/fitness.ts` 取，日期字符串统一用 `utils/fitness.ts` 的 `localDateStr`。
> - 现象：飞书客户端内免登拿到的 code，按扫码登录那套带 redirect_uri 换 token 报错。根因：`tt.requestAccess` 的 code 不绑定 redirect_uri。正确做法：`scene=fitness_h5` 换 token 时不传 redirect_uri，`fitness_oauth` 才传 `MobileRedirectUri`。
