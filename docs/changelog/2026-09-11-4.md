# 2026-09-11-4 CI deploy-frontend：scp $HOME 不可写 + ssh dash/pipefail

## 交接摘要（必读，写给下一个没有上下文的新会话）

**在做什么 / 目标**：

> 修 `deploy-frontend` 连续两处远端失败：① scp-action 写不可写 `$HOME`；② ssh-action 在 dash 下执行 `set -o pipefail`。

**已完成**：

> - 根因①：`ubuntu` HOME=`/home/work` 属主 `root:root`；drone-scp 默认中间 tar 落 `$HOME` → status 1。已加 `tar_tmp_path: /tmp/`（已合 `#12`）
> - 根因②：passwd shell 是 `/bin/sh`（dash），不支持 `pipefail`；ssh-action 按 login shell 跑 script → `Illegal option -o pipefail`。远端替换步骤改为 `bash <<'EOF' ... EOF`
> - 文件：[`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)；分支 `fix/0911_ci-scp-tar-tmp`

**当前状态（现在卡在哪 / 进行到哪一步）**：

> `#12` 已合 main；本分支在合入 main 后解决冲突，仅剩 bash/pipefail 修复待合。

**下一步计划**：

> 1. push 冲突解决后的分支，合 PR
> 2. 确认 `deploy-frontend` 全绿、飞书前端行绿
> 3. 打开 `https://oldbai.top/bgg/admin/dashboard` 验证新包与侧栏高亮

**踩过的坑 —— 绝对不要再犯**：

> - 现象：scp-action「scp file to server」status 1，SSH 其实已通。根因：`tar_tmp_path` 默认空 = 写 `$HOME`，而 `/home/work` root 属主不可写。正确做法：`tar_tmp_path: /tmp/`。
> - 现象：`sh: 1: set: Illegal option -o pipefail`。根因：bgg-dev `ubuntu` 的 login shell 是 dash；`set -euo pipefail` 只能在 bash。正确做法：ssh-action 的 script 用 `bash <<'EOF' ... EOF` 包一层（`${{ }}` 仍由 Actions 渲染），或改成 `set -eu` 且保证无 bash 语法。不要假设远端是 bash。
> - 现象：网上同类 scp 报错大量是「磁盘满」。根因：本机已核对不是。正确做法：先 `df -h` / `touch $HOME/...` / `touch /tmp/...` 三分法定位。
