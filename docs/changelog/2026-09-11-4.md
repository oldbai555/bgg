# 2026-09-11-4 CI deploy-frontend：scp-action 写不可写 $HOME

## 交接摘要（必读，写给下一个没有上下文的新会话）

**在做什么 / 目标**：

> Node 22 修复合入后，`deploy-frontend` 构建/打包已过，但 `appleboy/scp-action@v0.1.7` 在「scp file to server」失败：`error copy file to dest / Process exited with status 1`。

**已完成**：

> - 在 bgg-dev 排除磁盘满（根分区约 32%）、`/tmp` 可写、`/home/work/service/admin-frontend` 已是 `ubuntu` 属主
> - 根因：`ubuntu` 的 passwd HOME=`/home/work`，目录属主 `root:root`，用户不可写；drone-scp 未设 `tar_tmp_path` 时把中间 tar 落到 `$HOME` 相对路径，`scp -t` 写文件返回 status 1
> - [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) `deploy-frontend` 上传步骤增加 `tar_tmp_path: /tmp/`

**当前状态（现在卡在哪 / 进行到哪一步）**：

> 修复已写在工作区，待开分支 / PR 合入 main 后重跑 CD。

**下一步计划**：

> 1. 合 PR 到 main
> 2. 确认 Actions `deploy-frontend` 全绿、飞书前端部署行绿
> 3. 打开 `https://oldbai.top/bgg/admin/dashboard` 验证新包与侧栏高亮

**踩过的坑 —— 绝对不要再犯**：

> - 现象：SSH 能连（日志有 `remote server os type is unix`），但 scp-action 立刻 `Process exited with status 1`；同 secrets 的 `ssh-action`（deploy-dev）正常。根因：`target` 只是最终解压目录，中间上传路径由 `tar_tmp_path` 决定，默认空 = 写 `$HOME`；bgg-dev 把业务树挂在 root 属主的「假 HOME」`/home/work` 下。正确做法：CI 显式 `tar_tmp_path: /tmp/`（或把 `$HOME` 改成对 deploy 用户可写——改 HOME 属主影响面更大，默认不要动）。
> - 现象：网上同类报错大量是「磁盘满」。根因：本机已核对不是。正确做法：先 `df -h` / `touch $HOME/...` / `touch /tmp/...` 三分法定位，不要一上来清 Docker。
